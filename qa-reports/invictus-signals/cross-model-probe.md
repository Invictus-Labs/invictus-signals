## NEW_BUGS (triaged)

1. **P1 → disposition: documentation fix, not a code fix (FIXED this pass).** The intraday-percentile-vs-VWAP tension: `calculate_vwap` has no internal windowing (confirmed: no `period` parameter, sums the entire `candles` argument), unlike `intraday_ma_fast`/`intraday_ma_mid`/`intraday_adx`, which all internally bound themselves regardless of history depth. Widening `candles` to make `intraday_vol_lookback` meaningful therefore silently widens `vwap` too. **Verified this is not introduced by this PR**: invictus-bot's real candle buffers (500 × 1H bars, per Performance Sentinel's `entry.py` check) already span far more than one session, independent of whether `intraday_vol_lookback` is armed. The docstring previously presented "pass multi-session history" as a costless instruction; corrected to state the trade-off explicitly (this commit).
2. **P2 → disposition: FIXED this pass.** Invalid negative `vol_lookback`/`intraday_vol_lookback` (`<=1`) still ran the full-history rolling-width scan before `bbwp()` rejected it, because `daily_needed = vol_lookback + bb_period - 1` can reach 0 or negative, and `closes[-0:]` is the whole list. Measured 8.6x slower (0.330s → 0.038s baseline) at 200k candles. Fixed with a `> 1` guard mirroring `bbwp()`'s own rejection; 33ms measured post-fix.
3. **P2 → disposition: acknowledged, not fixed, out of territory.** `calculate_bb`'s variance step (`sum((p - middle) ** 2 for p in window)`) can raise `OverflowError` on candle closes near float64's representable magnitude (~1e308) — pre-existing code, not modified by this PR, shared by every other consumer of `calculate_bb` in the repo (not `bbwp`-specific). This PR does call `calculate_bb` more often per `compute_ta_state` invocation (once per rolling position instead of once), increasing exposure frequency to a pre-existing defect, but fixing float-overflow guarding belongs to `calculate_bb` itself, with its own repo-wide blast radius — outside this PR's additive-only scope. Flagged for a follow-up ticket.
4. **P2 → disposition: acknowledged, not fixed, out of territory.** `get_config(symbol)` with no overrides returns the shared `ASSET_PRESETS[symbol]` object directly (not a copy); mutating the returned `AssetConfig` mutates the global preset for every future caller. Pre-existing, `config.py` untouched by this PR. Every test in this PR that needed a modified config already passes explicit overrides (`get_config("BTC", bb_period=5)`), which correctly returns a fresh `dataclasses.replace()` copy per `config.py`'s own code — so this PR's own tests are unaffected — but flagged for a follow-up ticket since it's a real footgun for any future caller that mutates a no-override `get_config()` result in place.
